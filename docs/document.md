# Documents

These guides cover the documents in one index. You work with them through a collection, which `$sigmie->collect()` returns. [Core Concepts](core-concepts.md#documents-go-through-a-collection) explains how a collection relates to the index.

## Create a document

A `Document` wraps one JSON object. It holds any structure that PHP can encode as JSON:

```php
use Sigmie\Document\Document;

$doc = new Document([
    'title' => 'Inception',
    'director' => [
        'name' => 'Christopher Nolan',
        'born' => 1970,
    ],
    'cast' => [
        ['name' => 'Leonardo DiCaprio', 'role' => 'Cobb'],
        ['name' => 'Marion Cotillard', 'role' => 'Mal'],
    ],
]);
```

To choose the `_id` yourself, pass it as the second argument. Without it, Elasticsearch generates one on the first write:

```php
$doc = new Document(['title' => 'The Matrix'], 'matrix_1999');
```

Read and change fields with array access or properties. Array reads also accept dotted paths:

```php
$doc['title'] = 'New Title';
$doc['director.name'];      // 'Christopher Nolan'
$doc->title;                // 'New Title'
unset($doc['cast']);
```

## Get a collection

```php
$movies = $sigmie->collect('movies');
```

To make every write searchable before the call returns, pass `refresh: true`. Use it in tests:

```php
$movies = $sigmie->collect('movies', refresh: true);
```

> **Warning:** Do not use `refresh: true` in production. It forces a refresh on every write, which slows indexing.

## Add documents

To add many documents, call `merge()`. It sends one bulk request:

```php
$movies->merge([
    new Document(['title' => 'Snow White']),
    new Document(['title' => 'Cinderella']),
    new Document(['title' => 'Sleeping Beauty']),
]);
```

To add one document, call `add()`. It returns the document with its `_id` set:

```php
$doc = $movies->add(new Document(['title' => 'Mickey Mouse']));

$doc->_id;   // generated by Elasticsearch
```

`add()` only creates. If a document with the same `_id` exists, it throws `Sigmie\Base\ElasticsearchException`. To overwrite, see [Update a document](#update-a-document).

## Check documents against your properties

Pass your [properties](mappings.md) to the collection. Sigmie then checks each document before it writes the batch:

```php
use Sigmie\Mappings\NewProperties;

$props = new NewProperties;
$props->title('title');
$props->date('release_date');
$props->number('rating')->float();

$movies = $sigmie->collect('movies')->properties($props); // [tl! highlight]

$movies->merge([
    new Document([
        'title' => 'The Matrix',
        'release_date' => '1999-03-31',
        'rating' => 8.7,
    ]),
]);
```

If a value does not fit its property, such as a non-numeric `rating`, Sigmie writes nothing and throws `InvalidArgumentException`. The message starts with `Document validation failed:` and names each bad field. Sigmie checks only the fields that the properties define and skips `null` values.

The collection with properties also converts `DateTime` and `Carbon` values to the string format of the field, and generates embeddings for [semantic fields](semantic-search.md).

## Update a document

Pick the method by what should happen to the fields you leave out:

| Method | Fields you leave out |
|--------|----------------------|
| `replace()` | Removed |
| `merge()` | Kept |

To replace the whole document, call `replace()` with the same `_id`:

```php
$movies->replace(new Document([
    'title' => 'The Matrix',
    'year' => 1999,
], 'matrix_1'));
```

To change some fields and keep the rest, call `merge()` with the same `_id`. If no document has that `_id`, `merge()` creates it:

```php
$movies->merge([
    new Document(['rating' => 8.7], 'matrix_1'),
]);
```

## Read documents

```php
$movies->get('matrix_1');                        // one document, or null
$movies->getMany(['matrix_1', 'inception_1']);   // several, by _id
$movies->has('matrix_1');                        // true when the _id exists
$movies->count();                                // number of documents
$movies->take(10);                               // first 10 documents
$movies->random(5);                              // 5 random documents
$movies->toArray();                              // every document, keyed by _id
```

> **Warning:** `toArray()` loads the whole index into memory. Use it only on small indices. To go through a large index, see [Iterate over every document](#iterate-over-every-document).

To return only some fields, call `only()` or `except()` before `get()`, `getMany()`, `take()`, `random()`, or `each()`. Dotted paths reach nested fields:

```php
$movies->only(['title', 'year'])->random(5);
$customers->except(['contacts.email'])->getMany(['customer_1', 'customer_2']);
```

## Iterate over every document

`each()` visits every document in the index without loading the index into memory:

```php
$movies->each(function (Document $doc): void {
    echo $doc['title'] . "\n";
});
```

Sigmie reads 500 documents per request. To change the page size, call `chunk()`:

```php
$movies->chunk(100)->each(function (Document $doc): void {
    processOne($doc);
});
```

Sigmie pages with a point in time and `search_after`. The loop sees the index as it was when the loop started, so writes during the loop do not shift the pages.

To iterate over only the documents that match a search, use `each()` or `lazy()` on `newSearch()`. See [Iterating over all matching hits](search.md#iterating-over-all-matching-hits).

## Delete documents

```php
$movies->remove('matrix_1');                     // one document, by _id
$movies->remove(['matrix_1', 'inception_1']);    // several, in one bulk request
$movies->clear();                                // every document; the index stays
```

To delete the index itself, see [Delete an index](index.md#delete-an-index).

## Write values for typed fields

Some property types expect a specific value shape. [Mappings & Properties](mappings.md) lists the rules for each type.

A `date()` field takes a `Y-m-d` string. A `datetime()` field takes an ISO 8601 timestamp:

```php
$props->date('release_date');
$props->datetime('created_at');

new Document([
    'release_date' => '2023-04-07',
    'created_at' => '2023-04-07T12:38:29.000000Z',
]);
```

A `geoPoint()` field takes `lat` and `lon` keys:

```php
$props->geoPoint('location');

new Document([
    'venue' => 'Cinema Downtown',
    'location' => ['lat' => 40.7128, 'lon' => -74.0060],
]);
```

A `nested()` field takes a list of objects:

```php
$props->nested('cast', function (NewProperties $props) {
    $props->name('actor');
    $props->keyword('role');
});

new Document([
    'title' => 'Avengers',
    'cast' => [
        ['actor' => 'Robert Downey Jr.', 'role' => 'Iron Man'],
        ['actor' => 'Chris Evans', 'role' => 'Captain America'],
    ],
]);
```

To filter on the items of a nested field, see [Filter Parser](filter-parser.md#nested-field-filtering).

## Make writes visible to search

Elasticsearch makes a write searchable at the next refresh, about one second later by default. Until then, searches and `count()` do not see it:

```php
$movies = $sigmie->collect('movies');
$movies->add(new Document(['title' => 'Snow White']));
$movies->count();   // 0
sleep(1);
$movies->count();   // 1
```

For a batch import, write with the default and refresh once at the end:

```php
$movies = $sigmie->collect('movies');
$movies->merge($manyDocuments);
$movies->refresh(); // [tl! highlight]
```

`$sigmie->refresh('movies')` does the same without a collection.
